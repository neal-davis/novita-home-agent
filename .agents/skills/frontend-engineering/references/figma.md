# Figma 设计还原

当任务涉及 Figma 设计稿还原时，按本文档指导从设计稿提取信息并生成代码。

---

## 还原流程

```
收到设计稿（Figma 链接 / 截图 / 标注）
  ↓
① 结构拆解 — 模块树拆解、组件清单、图文关系识别 → 输出给用户确认
  ↓
①.5 自适应分析 — 断点覆盖判断、各断点布局差异、单断点推断 → 输出给用户确认
  ↓
② 设计值提取 — 颜色、间距、字号、圆角、阴影等映射到项目 token → 输出给用户确认
  ↓
③ 组件映射 — 判断哪些可复用已有组件、哪些需要新建
  ↓
③.5 图片资源处理 — 识别图片图层、确认下载路径（对接 localized-resources.md）
  ↓
④ 代码生成 — 按 workflow.md 的【生成（完整）】流程执行
  ↓
⑤ 视觉走查 — 对照设计稿逐项核对（含多断点验证）
```

---

## ① 结构拆解

**拆解是代码生成的前提，拆解结果须在动手前输出给用户确认。** 不要边拆边写——先完成完整的模块拆解，再进入后续流程。

### 识别维度

- **页面级布局** — 整体栅格、侧边栏/内容区/底部的划分
- **区块划分** — 哪些区域是独立的功能区块（可拆为独立组件）
- **组件层级** — 卡片里嵌套了什么？列表项内部结构是什么？层级不要超过 3 层
- **重复模式** — 设计稿中反复出现的结构，应抽为共享组件
- **图文关系** — 哪些是背景图、哪些是叠加文字、哪些是独立内容图（见 ③.5）

### 模块拆解输出格式

拆解完成后，列出模块树供用户确认，再进入下一步：

```
页面：[页面名]
├─ Layout / [LayoutName]          ← 页面框架（不含业务逻辑）
│   ├─ Header / [HeaderName]
│   └─ Main
│       ├─ [SectionA]             ← 独立区块 → 独立组件
│       │   ├─ [CardComponent]    ← 重复单元 → 共享组件
│       │   └─ [CardComponent]
│       └─ [SectionB]
└─ Footer / [FooterName]

组件清单：
  新建：[ComponentA]、[ComponentB]
  复用：[ExistingX]（已有，直接用）、[ExistingY]（需扩展 props）
  内联：[小结构，不值得独立抽组件]
```

### 拆分决策标准

| 判断                                     | 处理                                           |
| ---------------------------------------- | ---------------------------------------------- |
| 在设计稿中出现 ≥ 2 次                    | 抽为共享组件                                   |
| 有独立的交互状态（hover/active/loading） | 抽为独立组件                                   |
| 纯布局容器（无逻辑）                     | 可内联，不强制抽组件                           |
| 只在当前页面出现一次且无复用预期         | 按 code-layering.md 归属，可以是页面内局部组件 |

## ①.5 自适应分析

Figma 通常每个断点对应一份设计稿。收到设计稿后，先确认它代表哪个断点，其余断点按默认规则推断，代码生成时一并确认。

**确认当前设计稿断点：** PC（≥1280px）/ Tablet（768–1279px）/ Mobile（<768px）？

**其余断点默认推断：**

| 元素类型          | 推断行为                      |
| ----------------- | ----------------------------- |
| 多列网格（≥3 列） | Tablet → 2 列；Mobile → 单列  |
| 水平导航          | Mobile → Hamburger 或底部 Tab |
| 并排卡片 / 列表   | Mobile → 垂直堆叠             |
| 固定侧边栏        | Tablet/Mobile → 折叠为 Drawer |
| 大 Banner / Hero  | Mobile → 图片缩小，文字上移   |
| 表格              | Mobile → 横向滚动或卡片化     |

> 推断结果在代码生成前向用户确认一次，不自行决定。

## ② 设计值提取与 Token 比对

**不直接使用 Figma 的原始数值。** 按以下 7 个维度逐项提取，与项目 token 比对后输出映射表，交用户确认再进入代码生成。

> **Token 来源优先级（依次回退）：项目 `global-*` reference → `tailwind.config` → `theme.scss` → `_design-tokens.scss / CSS 变量`**
>
> - 命中 JieKou / Novita / PPIO 时，**以对应 `global-*` / `component-*` 的语义类名为唯一来源**，tailwind.config / theme.scss 只作验证，不作来源
> - 未命中品牌 reference 时，读 `tailwind.config` 中定义的 class 名；`theme.scss` 是构建中间层，不直接在代码中使用其变量名
> - Figma 原始值（hex / px）不得直接写入代码，无匹配 token 时提示用户确认是否扩展 token 体系

### 映射表输出格式

```
设计值 → Token 映射（待确认）：

| 维度     | 设计稿值                    | 匹配到的项目 Token              | 状态              |
|---------|-----------------------------|---------------------------------|-------------------|
| 颜色     | #6366F1                     | --color-brand                   | ✅ 匹配            |
| 颜色     | #FF4D4F                     | （无匹配）                       | ⚠️ 用 --color-error 还是新增？ |
| 文本     | 14px / 500 / 22px / 0px     | font-body-md                    | ✅ 匹配            |
| 文本     | 12px / 400 / 18px / 0.02em  | （无匹配）                       | ⚠️ 需确认          |
| 间距     | 16px 内边距                  | spacing-4                       | ✅ 匹配            |
| 圆角     | 20px                        | （最近 radius-lg=16px）          | ⚠️ 用 radius-lg 还是新增？ |
| 投影     | 0 2px 8px rgba(0,0,0,0.12)  | shadow-card                     | ✅ 匹配            |
| 边框     | 1px solid #E5E7EB            | border / --color-border         | ✅ 匹配            |
```

### 2.1 颜色系统

提取设计稿中出现的所有颜色，按语义分类：

| 语义类别      | 提取目标                                       |
| ------------- | ---------------------------------------------- |
| 主色 / 品牌色 | 按钮、链接、高亮、激活态                       |
| 功能色        | 成功（绿）、警告（黄）、错误（红）、信息（蓝） |
| 中性色        | 文字主色、文字次色、禁用色                     |
| 背景色        | 页面背景、卡片背景、悬浮层背景                 |
| 边框色        | 分割线、输入框边框、卡片描边                   |
| 遮罩色        | 弹窗遮罩、图片叠加层（含透明度）               |

> **透明度颜色**（如 `rgba(0,0,0,0.5)`）先确认项目中有无对应的 opacity token 或语义变量，不直接写 rgba。

---

### 2.2 文本布局

提取设计稿中每种文字样式的完整四元组：**字号 / 字重 / 行高 / 字间距**。

| 提取项           | 说明                                                              |
| ---------------- | ----------------------------------------------------------------- |
| `font-size`      | px 值 → 映射排版 token                                            |
| `font-weight`    | 100–900 → 映射 token（thin / regular / medium / semibold / bold） |
| `line-height`    | px 或倍数 → 映射行高 token                                        |
| `letter-spacing` | px 或 em → 映射字间距 token；0 或未设置也要显式标注               |

常见文字层级对照：

| Figma 图层语义     | 典型规格               | 对应 token 类别             |
| ------------------ | ---------------------- | --------------------------- |
| 页面标题 / H1      | 大字号 + Bold          | `heading-xl` / `heading-lg` |
| 区块标题 / H2–H3   | 中字号 + Semibold      | `heading-md` / `heading-sm` |
| 正文               | 14–16px + Regular      | `body-lg` / `body-md`       |
| 辅助说明 / Caption | 12px + Regular         | `body-sm` / `caption`       |
| 按钮文字           | 14px + Medium/Semibold | `label-md`                  |
| 数字 / 标签        | 根据设计标注           | 按排版 token 最近匹配       |

> **排版类名存在性：** 从 Figma 提取文字样式后，映射到项目排版工具类（如 `text-display-lg`、`text-heading-h1`、`text-paragraph`、`text-h6`）时，须先确认该类名已在项目 `global-*` reference 或 `tailwind.config.ts theme.extend` 中声明：
>
> - 已声明 → 直接使用
> - 未声明 → 不得凭 Figma 图层名自造类名；先用内置 Tailwind 文字类（`text-sm`、`text-base` 等）兜底，或提示用户补充声明，再使用
>
> **四元组部分不一致时的处理：** 排版类名通常封装了完整四元组（字号 / 字重 / 行高 / 字间距）。若 Figma 中某个属性与匹配到的类名不一致，**在使用该类名的同时，用对应的单属性工具类覆盖差异项**，而不是放弃类名改用裸值：
>
> ```tsx
> // 场景：text-heading-h1 = 24px/700/32px/0，但 Figma 的字间距是 0.02em
> // ✅ 用类名打底，单独覆盖字间距
> <h1 className="text-heading-h1 tracking-wide" />
>
> // 场景：text-body-md = 14px/400/22px，但 Figma 字重是 500（medium）
> // ✅ 覆盖字重
> <p className="text-body-md font-medium" />
>
> // ❌ 因一项不同就放弃类名，拆成四条裸值
> <p className="text-[14px] font-medium leading-[22px] tracking-[0]" />
> ```
>
> 覆盖的单属性值同样须使用 token 或 Tailwind 内置刻度，不写裸 px / em。
>
> 参见 [`fonts.md`](./fonts.md) 了解字体分层规范。

### 2.3 间距和布局

| 提取项                 | 说明                      |
| ---------------------- | ------------------------- |
| 内边距（padding）      | 组件内部四向间距          |
| 外边距（margin / gap） | 元素间距、栅格 gutter     |
| 区块间距               | Section 之间的垂直间距    |
| 内容区宽度             | 最大宽度约束（`max-w-*`） |
| 栅格列数               | 几列布局、列宽比例        |

> 间距值映射到项目 spacing scale（如 Tailwind 的 4 的倍数体系）；允许在最近 token 值内四舍五入，差距 > 4px 时提示用户确认。

---

### 2.4 圆角

| 提取项            | 说明                                   |
| ----------------- | -------------------------------------- |
| 按钮圆角          | 通常有全局统一值                       |
| 卡片 / 面板圆角   | 可能与按钮不同                         |
| 输入框圆角        | —                                      |
| 图片 / 头像圆角   | 注意全圆（`rounded-full`）与固定值区别 |
| 标签 / Badge 圆角 | 通常较大（胶囊形）                     |

> 圆角通常项目级统一，先查是否有全局 radius token；不同组件的差异值单独标注。

---

### 2.5 投影

提取投影的完整参数：`x偏移 y偏移 模糊半径 扩散半径 颜色（含透明度）`。

| 投影类型                 | 常见用途               |
| ------------------------ | ---------------------- |
| 轻投影（low elevation）  | 卡片、输入框 hover     |
| 中投影（mid elevation）  | 下拉菜单、浮层         |
| 重投影（high elevation） | 弹窗、Toast            |
| 内阴影（inset shadow）   | 输入框 focus、凹陷效果 |

> 多层投影叠加时逐层列出；颜色优先使用语义阴影 token（`shadow-sm / shadow-md / shadow-lg`），无匹配时提示用户新增。

---

### 2.6 边框和分割线

| 提取项           | 说明                                                |
| ---------------- | --------------------------------------------------- |
| 边框宽度         | 通常 1px，少数 2px                                  |
| 边框颜色         | 映射到 `--color-border` 或语义变量                  |
| 边框样式         | solid / dashed / dotted                             |
| 分割线           | 水平/垂直分割线的颜色和粗细                         |
| 描边与背景的关系 | 外描边（outline）vs 内描边（border）vs 阴影模拟描边 |

> 纯分割线（`<hr>` / 空 div）颜色通常与边框色一致，复用同一 token；若设计稿有独立分割线色，单独标注。

---

### 2.7 响应式

> 已在 ①.5 完成断点确认和推断，此处无需重复提取。代码生成时按 ①.5 结论实现 Tailwind 响应式前缀（`sm:` / `md:` / `lg:`）。

---

**原则：设计稿是视觉参考，token 是代码真相。** 有差异时由用户决定是适配已有 token 还是扩展 token 体系，Agent 不自行决定。

## ③ 组件映射

对照设计稿中的每个元素，判断来源：

```
设计稿中的元素
  ↓
项目中已有相同/相似组件？
  ├─ 有，完全匹配   → 直接使用
  ├─ 有，需要扩展   → 通过 props / variant 扩展，不 fork
  └─ 没有           → 新建，走 code-layering.md 归属判定
```

**注意：**

- 设计稿中的一个"组件"不一定对应代码中的一个组件——可能是多个已有组件的组合
- 不要因为设计稿长得像就新建组件，先查项目里有没有
- 设计稿中的命名（图层名）可作参考，但代码命名以项目约定为准

## ③.5 图片资源处理

设计稿中出现图片时，在进入代码生成前，先确认图片的下载位置和存放路径。

### 图文分离判断

| Figma 图层特征                  | 含义       | 代码实现方式                                                   |
| ------------------------------- | ---------- | -------------------------------------------------------------- |
| Frame/Rectangle 的 Image Fill   | 背景图     | CSS `background-image` 或 `<img>` + 绝对定位容器               |
| 图片图层上方叠有文字图层        | 图文叠加   | 父容器 `relative`，文字用独立 DOM 覆盖，**不**将文字烘焙进图片 |
| 独立图片图层（非 fill）         | 内容图     | `<img>` / `next/image`                                         |
| 图片内含固定文字（Banner/插图） | 含文字图片 | 图文拆分；若文字无法分离（设计限制），标注为多语言差异资源     |

### 下载地址确认流程

```
识别出图片资源
  ↓
确认项目资源管理方案（见 localized-resources.md）
  ├─ 构建前切换方案（locales/ 目录）
  │     ↓
  │   图片是否含语言相关文字？
  │     ├─ 是 → 每个语言各自提供版本，下载到 locales/<lang>/public/<path>
  │     └─ 否 → 通用资源，下载到所有语言目录 locales/*/public/<path> 保持一致
  │
  └─ 运行时 i18n 方案 / 无多语言
        ↓
      直接下载到 public/<path>
```

> 下载路径确认后，向用户列出清单并说明每张图片的目标路径，待确认后再生成引用代码。代码中统一通过 `/public/` 的相对路径引用，不写 `locales/` 路径（构建产物路径）。

## ④ 代码生成

按 [`workflow.md`](./workflow.md) 的【生成（完整）】流程执行。在 UI 组件步骤中：

- 布局用 Tailwind `flex` / `grid`，从设计稿推断布局意图而非像素级复制
- 间距、颜色、字号全部走 token，不写 Figma 标注的裸值
- 响应式行为从设计稿推断（如果有多端设计稿），没有时按移动端优先处理
- 图片资源路径以 ③.5 确认的下载位置为准；图标/未确认资源先用 placeholder 占位，标注 TODO

## ⑤ 视觉走查

代码生成后，对照设计稿逐项核对：

| 检查项       | 要点                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 布局结构     | 区块排列、嵌套层级与设计稿一致；组件边界正确                             |
| 颜色系统     | 主色/功能色/中性色/背景色/遮罩色均使用语义 token，无裸 hex 值            |
| 文本布局     | 字号、字重、行高、字间距四项均对齐排版 token；层级（标题/正文/辅助）清晰 |
| 间距和布局   | 内外边距、元素间距、区块间距对齐 spacing token（允许 scale 内四舍五入）  |
| 圆角         | 按钮/卡片/输入框/标签圆角使用正确的 radius token                         |
| 投影         | 投影层级（轻/中/重）使用正确的 shadow token；多层投影无遗漏              |
| 边框和分割线 | 边框宽度/颜色/样式正确；分割线颜色使用 token                             |
| 交互状态     | hover / focus / active / disabled / loading 覆盖完整                     |
| 响应式       | 当前断点还原准确；其余断点按 ①.5 推断结果正确适配                        |

## 常见问题

| 情况                                | 处理方式                                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------ |
| 设计稿的值在 token 中找不到精确匹配 | 用最近的 token 值，提示用户确认是否需要新增 token                                    |
| 设计稿标注与已有组件的默认值冲突    | 优先保持组件一致性，向用户说明差异                                                   |
| 设计稿只有一个断点                  | 按移动端优先实现，关键布局确保不在其他断点崩溃                                       |
| 设计稿中的图标没有对应资源          | 使用项目已有图标库中最接近的图标，标注 TODO 让用户补充                               |
| 图片图层上叠有文字                  | 图文分离实现，文字用真实 DOM，不烘焙进图片；见 ③.5                                   |
| 不确定图片该放哪个目录              | 先确认项目资源方案（构建前切换 vs 运行时 i18n），再按 ③.5 的下载流程列清单给用户确认 |
| 设计稿中含多语言差异图片（含文字）  | 各语言单独提供，下载到各 `locales/<lang>/public/` 目录；见 `localized-resources.md`  |
| 设计稿包含动效描述                  | 简单过渡用 CSS transition 实现；复杂动画先跳过，标注 TODO                            |
